# native/relay — scriptc-compiled NIP-01 relay

A single-file nostr relay compiled by [scriptc](https://github.com/sigilco/pyscriptc)'s
TypeScript subset into a static ELF: vendored `@chttp/router` + `@chttp/ws` for the
WebSocket transport, vendored `@cutils/sqlite` for embedded storage, and the shared
protocol core from `native/src/` (event validation, filter matching, vendored
BIP-340 schnorr + SHA-256).

`scriptc coverage native/relay/src/main.ts` → **100% static** (2839/2839 statements).

## What compiles

- **WebSocket server** — `@chttp/router` HTTP layer (a `GET /` status route) plus
  the `@chttp/ws` upgrade seam. All vendored sources live under `.vendor/` and are
  regenerated by `vendor.mjs` at build time (never edit them by hand).
- **NIP-01 protocol** — `EVENT` (validate → dedup/replace → store → `OK`), `REQ`
  (filters: `ids`, `authors`, `kinds`, `since`, `until`, `limit`, single-char `#tag`
  → `EVENT`* + `EOSE`), `CLOSE`, `NOTICE`/`CLOSED` error paths, multiple concurrent
  subscriptions per socket, per-connection sub caps.
- **Storage** — `SqliteEventStore` (`store.ts`) embeds `@cutils/sqlite` in the same
  ELF: `events`/`event_tags` tables, triggers, and the partial replaceable index
  ported from `migrations-sqlite/0001_core_schema.js`; NIP-16 ephemeral fanout-only,
  NIP-33 parameterized-replaceable upsert via
  `ON CONFLICT ... DO UPDATE ... WHERE event_created_at < excluded...`. The surface
  (`saveEvent`/`query`) is intentionally tiny so a `@cutils/postgres` adapter can
  slot in later.
- **Fanout** — in-process broadcast over open subscriptions (the Redis `xAdd`/`xRead`
  broadcast stream is replaced by a direct per-connection match loop — correct for
  the single-process topology this binary runs).

## Config

Env vars: `RELAY_PORT` (8008), `RELAY_DB_FILE` (`relay.db`, `:memory:` allowed),
`RELAY_MAX_SUBS` (16), `RELAY_MAX_FILTERS` (8), `RELAY_DEFAULT_LIMIT` (100),
`RELAY_MAX_LIMIT` (500), `RELAY_MAX_CONTENT_BYTES` (65536),
`RELAY_SKIP_SIG_VERIFY` (bench aid — never in production).

Reproduce: `bench/run.sh` (driver: `bench/measure.cjs` + `bench/load.cjs`).
Both sides verify Schnorr signatures; the stock relay runs on the
`devin/1791411469-sqlite-poc` worktree (`/home/ubuntu/repos/nostream-sqlite`) with
localhost whitelisted from rate limits (`bench/nostr-config/settings.yaml`).

Honest read: ~62% of stock throughput — the native binary is a single OS thread
doing signature verify + JSON parse + sqlite write inline, while upstream fans
storage out to worker threads. In exchange you get a 5MB statically-linked binary
with a 254× smaller resident footprint and ~23× faster cold start.

## Excluded (stays outside scriptc)

- **knex migrations** — operator tooling, not runtime code. Ops flow:
  `knex migrate:latest` runs the existing migrations against the DB file, then the
  ELF boots. The embedded `SCHEMA_SQL` in `schema.ts` exists for standalone/dev
  bootstraps; it is a flattened subset (events/event_tags + replaceable index) and
  is *not* a migration system.
- **express HTTP admin/status APIs** — currently only `GET /` text status exists.
  Candidate for a stacked PR porting the admin endpoints onto `@chttp/router`
  inside the same binary.
- **Redis rate limiting** — the Lua EWMA/token-bucket scripts in
  `src/cache/sqlite-cache.ts` are Node-side; a TS-in-subset port is a candidate
  stacked PR.
- **Redis broadcast fanout (`xAdd`/`xRead`)** — replaced by in-process pub/sub.
  Valid because the ELF is single-process; a multi-binary deployment would need
  the stream replacement back (candidate stacked PR over `@cutils/cache` or kept
  Node-side).
- **node:cluster / worker_threads** — not ported; the relay is deliberately one
  process (documented bottleneck above).
- **pino logging** — minimal `console.log` console logger instead.
- **zod schemas** — hand-validated JSON in `proto.ts` (scriptc can't lower zod).
- **@logtape/logtape** — evaluated and rejected: it pulls in a large surface the
  subset can't lower; the console logger keeps the diff small.

## Maintenance weight

Self-contained: everything lives under `native/relay/` (`src/`, `vendor.mjs`,
`build.sh`, `bench/`), `.vendor/` is regenerated, and `dist/` is gitignored.
Upstream drift in `src/` touches it only via the shared protocol core
(`native/src/types.ts`, `event.ts`) — filter-shape or Event-field changes require
mirroring in `proto.ts`/`store.ts`, which is exactly the seam a maintenance-heavy
design would hide; here it is explicit and small.

Build: `bash native/relay/build.sh` → `native/relay/dist/nostream-native`.
Requires `@cutils/sqlite` with the `./elf` FFI entry and zig (clang shim synthesized
by the script).
